# 和风天气作业：从注册到真实调用

目标：输入经纬度和预报天数，向和风天气发送 HTTPS GET 请求，解析真实 JSON，显示天气并可保存原始响应。

## 1. 安装依赖

在本文件所在目录打开终端，使用你正在学习 Python 的环境：

```powershell
python -m pip install -r requirements.txt
```

## 2. 注册并创建项目

1. 打开 https://dev.qweather.com/ ，进入控制台，完成账户注册与页面要求的验证。
2. 在“项目管理”中创建项目，例如“Python天气作业”。
3. 记下项目 ID；在“设置”中找到开发者 ID 和你专属的 API Host。
4. 以下使用 JWT 认证，与作业中的“请求头 token”相对应。不要把 API Key 当作 Bearer token 使用。

官方定价文档当前显示：天气和基础服务这一价格分组每月合计前 50,000 次请求单价为 0。按本教程少量手动测试，在该额度内完成；不需要为本示例购买节省计划或充值。免费额度不是无限请求；如果账户提示其他开通要求，以控制台页面为准。

## 3. 生成密钥并添加 JWT 凭据

只需生成一次：

```powershell
python weather_tool.py keygen
```

生成两个文件：

- `keys/ed25519-private.pem`：私钥，留在本机，用于签发 token。
- `keys/ed25519-public.pem`：公钥，用记事本打开，复制全部内容，包括 BEGIN/END 两行。

回到控制台，打开项目，点击“添加凭据”，选择“JSON Web Token”，填写名称，粘贴公钥并保存。记下新生成的凭据 ID。

程序在每次查询时自动生成约 15 分钟有效的 token，不必手动复制 token，也不用额外找一个“获取 token”的接口。

## 4. 填写配置

```powershell
Copy-Item config.example.json config.json
```

用编辑器修改 `config.json`：

| 配置名 | 填写内容 |
| --- | --- |
| api_host | 控制台“设置”中的专属域名，只写域名，不加 https:// |
| developer_id | 开发者 ID，认证文档中对应 iss |
| project_id | 项目 ID，认证文档中对应 sub |
| credential_id | JWT 凭据 ID，认证文档中对应 kid |
| private_key_path | 保留 keys/ed25519-private.pem 即可，相对配置文件定位 |

这三个 ID 各不相同。私钥和 token 不要放进作业截图或公开仓库；提交代码时使用配置示例文件。

## 5. 查询真实天气

北京示例位置：

```powershell
python weather_tool.py forecast --lat 39.92 --lon 116.41 --days 3 --save weather_result.json
```

成都示例位置：

```powershell
python weather_tool.py forecast --lat 30.67 --lon 104.07 --days 3 --save weather_result.json
```

这里查询的是示例坐标所在位置。工具当前接受坐标；若想直接输入城市名，可后续增加 GeoAPI 城市搜索。

成功时终端显示预报时段、白天/夜间天气、最高/最低温与单位。`weather_result.json` 保存这次 API 实际返回的数据。只有实际运行成功后的输出，才是作业的真实调用证据。

## 6. 读懂请求

```http
GET /weather/v1/daily/39.92/116.41?days=3&localTime=true&lang=zh HTTP/1.1
Host: 你自己的APIHost
Authorization: Bearer 你生成的JWT
```

- GET：读取天气资源，代码对应 `requests.get(...)`。
- `/weather/v1/daily`：接口路径，表示每日天气预报。
- `39.92`、`116.41`：路径参数，先纬度、后经度，文档要求最多两位小数。
- `?` 后面：查询参数；days 为天数，localTime 为是否返回查询地点本地时间，lang 为语言。
- `Authorization`：请求头；Bearer 后一个空格，再接完整 JWT。
- 本例不发送 JSON 请求体，地点在 URL 中，认证信息在请求头中。

JWT 由程序使用私钥在本地签发。JWT Header 包含 alg、kid；Payload 包含 iss、sub、iat、exp。不要把这些 JWT 内部字段与整个 HTTP 请求头混淆。

## 7. 读懂返回结构

当前 `/weather/v1/daily/...` 接口中：

```python
data = response.json()  # JSON 对象 -> Python dict
day = data["days"][0]  # days 数组 -> list，第一个元素是第一段每日预报
high = day["temperatureMax"]["value"]
unit = day["temperatureMax"]["unit"]
condition = day["daytime"]["condition"]["text"]
```

`metadata` 包含来源等元信息；`days` 是每日预报列表；每项包含预报起止时间、温度对象、daytime 和 nighttime 等。显示温度时读取 unit，不凭空假定单位。保留完整预报起止时间，避免将预报区间直接误当成从午夜开始的自然日。

注意：文档也有“城市每日预报”v7 接口，那套使用 location 查询参数及 daily 等返回字段。不要将 v7 的地址、参数和解析代码与本例 v1 混用。

## 8. 作业提交建议

1. 项目创建截图，遮住凭据和敏感信息。
2. 自己读过的官方接口文档链接。
3. `weather_tool.py`、`requirements.txt` 和 `config.example.json`。
4. 自己实际运行成功的终端截图与 `weather_result.json`。
5. 用自己的话解释 GET、Authorization、路径参数、查询参数、dict/list 取值及异常处理。

常见错误：401 先检查三个 ID、公私钥匹配、Host 和电脑时间；404 核对路径；429 查看请求限制；网络异常检查连接。工具不会用虚构天气替代失败结果。
