## 1. RCC_CFGR 里 PLLMUL 位怎么配置成 9 倍频？
- 路由：rm → hal
- 命中来源：RM0008；片段 13 个；耗时 6.2s
- 答案：

资料同时给出了两个版本的 RCC_CFGR，PLLMUL 编码不同，需先区分型号：

- **STM32F101/102/103/104（第 7 章）**：PLLMUL[3:0] = `0111` 表示 PLL input clock x 9 [4]。
- **STM32F105/107（第 8 章，Connectivity line）**：PLLMUL[3:0] = `0111` 同样表示 PLL input clock x 9 [2]。

两版在该编码上一致，配置方法：

1. PLLMUL 位于 RCC_CFGR 的 **Bits 21:18**，地址偏移 **0x04**，复位值 **0x0000 0000** [1][3]。
2. 该位只能在 **PLL 关闭（PLLON=0）时**写入 [2][4]。
3. 写入 `0111` 即得到 9 倍频；注意 PLL 输出频率不得超过 72 MHz [2][4]。

补充差异：F105/107 的 PLLMUL 编码表中 `000x`、`10xx`、`1100`、`111x` 为 Reserved，另有 `1101` 表示 x 6.5 [2]；F101/102/103/104 的编码表为 `0000`～`1111` 连续对应 x 2～x 16（`1110`、`1111` 均为 x 16）[4]。
- 出处：[1,2] 8 Connectivity line devices: reset and clock control (RCC) > 8.3 RCC registers > 8.3.2 Clock configuration register (RCC_CFGR)｜p.133-136（同节 2 块）；[3,4] 7 Low-, medium-, high- and XL-density reset and clock control (RCC) > 7.3 RCC registers > 7.3.2 Clock configuration register (RCC_CFGR)｜p.100-102（同节 2 块）；[5] 8 Connectivity line devices: reset and clock control (RCC) > 8.2 Clocks > 8.2.3 PLLs｜p.128-128；[6,7] 8 Connectivity line devices: reset and clock control (RCC) > 8.3 RCC registers > 8.3.12 Clock configuration register2 (RCC_CFGR2)｜p.153-155（同节 2 块）；[8,9,10] 7 Low-, medium-, high- and XL-density reset and clock control (RCC) > 7.3 RCC registers > 7.3.11 RCC register map｜p.120-121（同节 3 块）；[11,12,13] 8 Connectivity line devices: reset and clock control (RCC) > 8.3 RCC registers > 8.3.13 RCC register map｜p.155-157（同节 3 块）

## 2. TIMx_PSC 预分频寄存器的作用是什么？
- 路由：rm → hal
- 命中来源：RM0008；片段 6 个；耗时 4.8s
- 答案：

TIMx_PSC 是 16 位预分频寄存器，作用是设定送入计数器的时钟 CK_CNT 相对于预分频器输入时钟 fCK_PSC 的分频比。

**1. 寄存器基本信息**
- 地址偏移：0x28
- 复位值：0x0000
- 位域：Bits 15:0 PSC[15:0]，读写（rw）

以上信息在 TIM6/TIM7、TIM2~TIM5、TIM1/TIM8、TIM9~TIM14 各版本中一致 [1][2][3][4][5]。

**2. 分频关系**
计数器时钟频率 CK_CNT = fCK_PSC / (PSC[15:0] + 1) [1][2][3][4][5]。也就是说，预分频系数可以是 1 到 65536 之间的任意值 [6]。

**3. 写入值的生效时机**
PSC 中写入的值不会立即生效，而是在每个更新事件（update event）时被加载到当前工作的预分频寄存器中；通过 TIMx_EGR 的 UG 位清零计数器、或在“reset mode”下由触发控制器清零计数器时，也属于这类更新事件 [1][2][3][4][5]。由于 TIMx_PSC 带缓冲，可以在运行中修改分频比，新分频比从下一个更新事件起才被采用 [6]。

**4. 配置方法**
要得到分频系数 N（1 ≤ N ≤ 65536），向 PSC[15:0] 写入 N−1 即可，例如需要 1 分频时写 0x0000（复位值即 1 分频）。
- 出处：[1] 17 Basic timers (TIM6 and TIM7) > 17.4 TIM6 and TIM7 registers > 17.4.7 TIM6 and TIM7 prescaler (TIMx_PSC)｜p.479-479；[2] 15 General-purpose timers (TIM2 to TIM5) > 15.4 TIMx2 to TIM5 registers > 15.4.11 TIMx prescaler (TIMx_PSC)｜p.417-418；[3] 14 Advanced-control timers (TIM1 and TIM8) > 14.4 TIM1 and TIM8 registers > 14.4.11 TIM1 and TIM8 prescaler (TIMx_PSC)｜p.355-355；[4] 16 General-purpose timers (TIM9 to TIM14) > 16.5 TIM10/11/13/14 registers > 16.5.8 TIM10/11/13/14 prescaler (TIMx_PSC)｜p.465-465；[5] 16 General-purpose timers (TIM9 to TIM14) > 16.4 TIM9 and TIM12 registers > 16.4.9 TIM9/12 prescaler (TIMx_PSC)｜p.455-455；[6] 17 Basic timers (TIM6 and TIM7) > 17.3 TIM6 and TIM7 functional description > 17.3.1 Time-base unit > Prescaler description｜p.470-471

## 3. STM32F103C8T6 的 Flash 和 SRAM 各有多大？
- 路由：ds → rm → hal
- 命中来源：DS；片段 9 个；耗时 4.9s
- 答案：

STM32F103C8T6 属于 STM32F103Cx、64 Kbytes Flash 的型号：

- **Flash：64 Kbytes**。订货编号中“8 = 64 Kbytes of Flash memory”[7]；器件特性表里 STM32F103Cx 的 Flash 一列为 64 / 128 Kbytes 两档[1]。
- **SRAM：20 Kbytes**。器件特性表中 STM32F103Cx 的 SRAM 为 20 Kbytes[1]；正文也说明该系列 SRAM 最大 20 Kbytes[4]。

补充：该型号为 48 引脚（C = 48 pins）、LQFP48/UFQFPN48 封装[2][7]，属于 medium-density 器件（STM32F103x8/B）[6]。
- 出处：[1,2,3] 2 Description > 2.1 Device overview｜p.10-12（同节 3 块）；[4] 2 Description｜p.9-9；[5,6] 2 Description > 2.2 Full compatibility throughout the family｜p.13-13（同节 2 块）；[7] 7 Ordering information scheme｜p.108-108；[8] 1 Introduction｜p.9-9；[9] 2 Description > 2.3 Overview > 2.3.1 ARM® Cortex®-M3 core with embedded Flash and SRAM｜p.14-14

## 4. STM32F103C8T6 是什么封装，有多少个引脚？
- 路由：ds → rm → hal
- 命中来源：DS；片段 10 个；耗时 3.2s
- 答案：

STM32F103C8T6 是 **LQFP48** 封装（48 引脚）。

依据：
- 订货型号编码中，引脚数字母 **C = 48 pins**，封装字母 **T = LQFP** [1]。
- 器件总览表中 STM32F103Cx 对应封装为 **LQFP48, UFQFPN48** [2]。

注：同型号的 UFQFPN48 也是 48 引脚封装，但 T6 中的 T 指 LQFP [1]。
- 出处：[1] 7 Ordering information scheme｜p.108-108；[2,3,4] 2 Description > 2.1 Device overview｜p.10-12（同节 3 块）；[5,6,7] 3 Pinouts and pin description｜p.21-33（同节 3 块）；[8,9] 2 Description > 2.2 Full compatibility throughout the family｜p.13-13（同节 2 块）；[10] 1 Introduction｜p.9-9

## 5. HAL_UART_Transmit 的参数分别是什么？
- 路由：hal → um → examples
- 命中来源：HAL；片段 7 个；耗时 4.0s
- 答案：

`HAL_UART_Transmit` 的参数共 4 个 [1]：

- `huart`：`UART_HandleTypeDef *`，指向包含该 UART 模块配置信息的句柄结构体 [1]
- `pData`：`const uint8_t *`，数据缓冲区指针（u8 或 u16 数据元素）[1]
- `Size`：`uint16_t`，要发送的数据元素个数（u8 或 u16）[1]
- `Timeout`：`uint32_t`，超时时间 [1]

补充说明：当 UART 校验未使能（PCE = 0）且字长配置为 9 位（M1-M0 = 01）时，发送数据按 u16 处理，此时 `Size` 须表示通过 `pData` 提供的 u16 个数 [1]。函数返回 `HAL_StatusTypeDef` 类型的 HAL 状态 [1]。
- 出处：[1,2,3,7] Src/stm32f1xx_hal_uart.c（同节 4 块）；[4,5] Inc/stm32f1xx_hal_uart.h（同节 2 块）；[6] Src/stm32f1xx_hal_usart.c

## 6. HAL_GPIO_Init 的 Mode 成员可以取哪些值？
- 路由：hal → um → examples
- 命中来源：HAL, UM1850；片段 7 个；耗时 4.9s
- 答案：

`GPIO_InitTypeDef::Mode` 用于指定所选引脚的工作模式，取值来自 `GPIO_mode_define` [1][4]。资料中列出的取值如下 [7]：

- `GPIO_MODE_INPUT` = 0x00000000u（Input Floating Mode）
- `GPIO_MODE_OUTPUT_PP` = 0x00000001u（Output Push Pull Mode）
- `GPIO_MODE_OUTPUT_OD` = 0x00000011u（Output Open Drain Mode）
- `GPIO_MODE_AF_PP` = 0x00000002u（Alternate Function Push Pull Mode）
- `GPIO_MODE_AF_OD` = 0x00000012u（Alternate Function Open Drain Mode）
- `GPIO_MODE_AF_INPUT` = `GPIO_MODE_INPUT`（Alternate Function Input Mode）
- `GPIO_MODE_ANALOG` = 0x00000003u（Analog Mode）
- `GPIO_MODE_IT_RISING` = 0x10110000u（External Interrupt Mode with Rising edge trigger detection）
- `GPIO_MODE_IT_FALLING` = 0x10210000u（External Interrupt Mode with Falling edge trigger detection）
- `GPIO_MODE_IT_RISING_FALLING` = 0x10310000u（External Interrupt Mode with Rising/Falling edge trigger detection）
- `GPIO_MODE_EVT_RISING` = 0x10120000u（External Event Mode with Rising edge trigger detection）[3]
- `GPIO_MODE_EVT_FALLING` = 0x10220000u（External Event Mode with Falling edge trigger detection）[3]
- `GPIO_MODE_EVT_RISING_FALLING` = 0x10320000u（External Event Mode with Rising/Falling edge trigger detection）[3]

`HAL_GPIO_Init` 内部通过 `assert_param(IS_GPIO_MODE(GPIO_Init->Mode))` 校验该成员，`IS_GPIO_MODE` 允许的取值集合与上表一致（含 `GPIO_MODE_ANALOG`）[2][6]。其中 `GPIO_MODE_INPUT`、`GPIO_MODE_IT_*`、`GPIO_MODE_EVT_*` 在初始化时按输入处理，并会校验 `Pull` 参数 [5]。
- 出处：[1] 20 HAL GPIO Generic Driver > 20.1 GPIO Firmware driver registers structures > 20.1.1 GPIO_InitTypeDef｜p.225-225；[2,3,4,7] Inc/stm32f1xx_hal_gpio.h（同节 4 块）；[5,6] Src/stm32f1xx_hal_gpio.c（同节 2 块）

## 7. __HAL_RCC_GPIOA_CLK_ENABLE 宏最终操作哪个寄存器？
- 路由：rm → hal
- 命中来源：HAL；片段 6 个；耗时 5.5s
- 答案：

`__HAL_RCC_GPIOA_CLK_ENABLE` 宏最终操作的是 **RCC->APB2ENR** 寄存器，置位其中的 **RCC_APB2ENR_IOPAEN** 位（随后回读该位以产生使能后的延时）[6]。

对应的关闭宏 `__HAL_RCC_GPIOA_CLK_DISABLE()` 也是操作同一寄存器，清零 `RCC_APB2ENR_IOPAEN` 位 [5]。
- 出处：[1,5,6] Inc/stm32f1xx_hal_rcc.h（同节 3 块）；[2] Src/stm32f1xx_hal_rcc.c；[3,4] Inc/stm32f1xx_hal_rcc_ex.h（同节 2 块）

## 8. HAL_ADC_Start 可能返回哪些状态？
- 路由：hal → um → examples
- 命中来源：HAL；片段 8 个；耗时 3.7s
- 答案：

`HAL_ADC_Start` 的返回值类型是 `HAL_StatusTypeDef`，可能取值为 `HAL_OK`、`HAL_ERROR`、`HAL_BUSY`、`HAL_TIMEOUT` [8]。

函数内部的实际返回路径：先调用 `ADC_Enable(hadc)` 并把结果存入 `tmp_hal_status`，只有 `tmp_hal_status == HAL_OK` 时才继续启动规则组转换；函数最终返回该 `tmp_hal_status` [1]。也就是说，ADC 使能失败时返回 `ADC_Enable` 给出的错误状态，使能成功时返回 `HAL_OK`。

另外，函数开头执行 `__HAL_LOCK(hadc)`，若句柄已被占用会返回 `HAL_BUSY`（该分支在资料片段中未完整给出，资料中未给出其具体代码）。
- 出处：[1,3,4,5,6] Src/stm32f1xx_hal_adc.c（同节 5 块）；[2,7] Inc/stm32f1xx_hal_adc.h（同节 2 块）；[8] Inc/stm32f1xx_hal_def.h

## 9. GPIO 例程里 LED 闪烁是怎么实现的？
- 路由：examples → hal → um
- 命中来源：HAL_EXAMPLE；片段 6 个；耗时 7.9s
- 答案：

GPIO 例程（GPIO/GPIO_IOToggle）的 LED 闪烁实现方式如下：

1. **初始化**：先调用 `HAL_Init()`，再通过 `SystemClock_Config()` 把系统时钟配置为 64 MHz [1]。
2. **使能 GPIO 时钟**：调用 `LED2_GPIO_CLK_ENABLE()`，以便能够编程配置寄存器 [1]。
3. **配置 IO 为推挽输出**：设置 `GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP`、`GPIO_InitStruct.Pull = GPIO_PULLUP`、`GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH`，引脚为 `LED2_PIN`，端口为 `LED2_GPIO_PORT`，然后调用 `HAL_GPIO_Init(LED2_GPIO_PORT, &GPIO_InitStruct)` [1]。
4. **循环翻转**：在 `while (1)` 中调用 `HAL_GPIO_TogglePin(LED2_GPIO_PORT, LED2_PIN)` 翻转 LED2 引脚电平，随后 `HAL_Delay(100)` 延时 100 ms，形成闪烁效果 [1]。

即：推挽输出配置 + 无限循环中每 100 ms 翻转一次引脚电平 [1]。
- 出处：[1] GPIO/GPIO_IOToggle/Src/main.c；[2] SPI/SPI_FullDuplex_ComDMA/Src/main.c；[3,6] I2C/I2C_TwoBoards_ComDMA/Src/main.c（同节 2 块）；[4,5] I2C/I2C_TwoBoards_ComIT/Src/main.c（同节 2 块）

## 10. 用 HAL 让 PA5 输出高电平，底层写的是哪个寄存器？
- 路由：rm → hal
- 命中来源：RM0008；片段 6 个；耗时 3.9s
- 答案：

用 HAL 让 PA5 输出高电平，底层最终写的是 **GPIOA_BSRR**（Bit Set/Reset Register）。

依据：手册说明在 bit 级修改 GPIOx_ODR 不需要关中断，只要向 **GPIOx_BSRR**（或仅用于复位的 GPIOx_BRR）中对应位写 ‘1’，即可在一次原子 APB2 写访问中只修改选中的位，未选中的位不受影响 [1]。因此置位 PA5 就是向 GPIOA_BSRR 的对应置位位写 1。

补充：PA5 同时也是 SPI1_SCK 的默认复用功能引脚（SPI1 REMAP=0 时）[3]，若该脚被配置为 SPI1 复用功能，则置位 BSRR 不一定反映到引脚电平上；作为普通 GPIO 输出使用时按上述方式操作即可。
